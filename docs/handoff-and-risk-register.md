# 交接说明与风险登记

## 1. 角色交接顺序

### 1.1 产品人员交给系统设计人员

产品侧已明确：

- 产品定位：副业/兼职风险识别工具。
- 核心用户：想做副业但缺少辨别能力的新手。
- 核心功能：查项目、测文案、做适配、看榜单。
- 明确边界：不卖课、不招聘、不导流、不承诺收益、不做 UGC。
- 首批内容：30 条项目卡、50 条风险词/组合规则。

系统设计人员需要基于这些边界继续细化：

- 数据库建模。
- 小程序页面流。
- 风险规则引擎。
- AI 解释服务边界。
- 运营后台与内容审核流程。

### 1.2 系统设计人员交给开发人员

系统侧已明确：

- 页面清单。
- API 草案。
- 数据表字段。
- 风险评分规则。
- 检测流程。
- 状态流转。

开发人员需要按里程碑实现：

1. 项目库和搜索。
2. 文案风险检测。
3. AI 辅助解释。
4. 适配测试。
5. 内容维护后台。
6. 提审与灰度。

## 2. 当前已补充的关键考虑

### 2.1 不做前台 UGC

原因：兼职/副业主题容易被广告、诈骗、导流内容污染。  
决策：MVP 仅允许反馈进入后台，不做评论区、投稿广场和项目发布。

### 2.2 默认不保存检测原文

原因：用户可能粘贴聊天记录、手机号、微信号、转账信息等敏感内容。  
决策：默认只保存哈希、风险等级和命中规则。历史记录需用户主动开启。

### 2.3 AI 不做最终判定

原因：AI 可能误判、降级高危内容，或生成不合规教程。  
决策：规则引擎先判定，AI 只解释；强规则命中后等级锁定。

### 2.4 广告延后上线

原因：首版提审时广告容易增加审核变量，也可能损伤用户信任。  
决策：MVP 提审前关闭广告，灰度稳定后再接入原生广告或激励广告。

### 2.5 项目卡不提供外部跳转

原因：外链、群、课程、平台跳转容易被误认为导流。  
决策：MVP 只做信息展示，不提供加入项目、购买课程、联系导师等入口。

## 3. 未决策项

### D001 小程序服务类目

风险：如果选择招聘、金融、资讯等类目，可能触发资质或更严格审核。  
建议：开发前在微信公众平台后台确认可选类目，优先选择工具/效率/生活服务方向。  
负责人：产品 + 小程序主体负责人。  
状态：待确认。

### D002 小程序名称

备选：

- 副业风险雷达
- 兼职风险体检
- 副业避坑助手

建议优先：兼职风险体检。  
原因：比“副业”更工具化，比“赚钱”更安全。  
状态：待确认。

### D003 AI 模型供应商

风险：不同模型在内容安全、响应速度、成本和稳定性上差异明显。  
建议：先实现可插拔接口，首版规则引擎可独立运行；AI 失败不影响检测结果。  
状态：待技术选型。

### D004 内容后台形态

选项：

- 简易数据库管理。
- 低代码 CMS。
- 自研后台。

建议：MVP 用低代码 CMS 或数据库管理，等内容更新频率稳定后再自研。  
状态：待技术负责人确认。

### D005 广告接入时间

建议触发条件：

- DAU 连续 7 天超过 500。
- 项目详情页日 PV 超过 2000。
- 风险检测结果页日 PV 超过 500。
- 内容误判反馈可控。

状态：后置。

## 4. 风险登记

| 风险 | 影响 | 缓解方案 |
|---|---|---|
| 被审核理解为赚钱项目平台 | 提审失败 | 名称、首页、详情页都强调风险识别，不展示收益诱导 |
| 用户提交诈骗广告污染内容 | 内容安全风险 | 不做前台 UGC，反馈仅后台可见 |
| AI 输出违规操作步骤 | 审核与安全风险 | 强系统提示词 + 输出过滤 + 规则优先 |
| 用户粘贴敏感聊天记录 | 隐私风险 | 默认不保存原文，输入侧提示用户勿粘贴敏感信息 |
| 风险检测误判 | 信任下降 | 提供反馈入口，风险解释显示命中依据 |
| 广告内容误导 | 信任和合规风险 | 广告延后接入，广告与内容明确区分 |
| 项目库更新不及时 | 用户留存下降 | 记录无结果搜索词，每周补充高频项目 |

## 5. 下一步建议

1. 先确认小程序主体和服务类目。
2. 让设计人员按 `design/system-design.md` 出低保真页面。
3. 让开发人员按 M1、M2 先做无 AI 版本。
4. 运营继续把项目库从 30 条补到 80 条。
5. 灰度测试后再决定是否接 AI 和广告。
